# lore-text — 世界觀資料（content/lore）與文字潤飾準則

[content README](README.md)｜格式契約 [lore README](../../../content/lore/README.md)｜風格 [style.md](../../../content/lore/style.md)（用語表 glossary.json 23 列）｜既有 REPORT `wf/workflows/dispatch/handoffs/plan-lore/REPORT.md`（替使用者做掉的決定與衝突清單）

**先讀** [world-pillars](world-pillars.md)（世界觀設計支柱 31 條與最常見的違反）——lore 與潤飾最常踩的就是那張清單。

## lore 的優先序與一致性

設定優先序：使用者裁示（design-notes）＞ world spec ＞ lore。lore 不得與前兩者衝突；發現 spec 內部矛盾寫 REPORT，不在 lore 裡改。既有：勢力 31、人物 58、事件 53、地點 49、時代 7、年表 111。新增前先 `ls` 同類資料夾與 `grep` 名字，避免撞名（已發生：白夜 A 級摹機 vs 菌床白夜；irina-sokolova 撞名已改）。

**年表一致性**：七時代——先民之潮（-9000～-8800）、舊世界（2029～2089-03）、第一次潮（2089-03～2090）、摹機黎明（2091～2094）、軛鞍年代（2095～2100）、蝕線時代（2101～2105）、殘聯時代（2106～現在）。錨點日期不可動：2041 靜海市、2089-03-14 第一次潮、2089-05 夸父認主、2091 摹一、2093-02 堅盾公刻、2095 拾號、2097 月面背面、2101 蝕線協定、2102 銀環墜機／長槍流出、2103 刑天出土、2104 第一個登錄機魂、2105 浦那／無肉者宣言、2106 殘聯成立、2107 綠線清剿、2108-01 開場。新事件要掛 `period`（era）且 date 落在該時代內；`timeline.json` 依 date 升冪、開場後條目一律 tag `rumor`。大潮只在第 1／15 天、弦月第 7／21 天——寫日期時對一下。

## 勢力（factions）

大勢力 body 必含四小節：`## 軍事組織與作戰風格`、`## 對傭兵：態度與補給`、`## 藍本古代機與研發路線`、`## 外交`。一個勢力要有史詩：一台藍本古代機（`ancientMech`）、一條研發血統（`mechSeries` 與 base frames 的 `lineage-*` 對齊）、一場代表性戰役、一次背盟或結盟；`relations` 反映 2108 當下（同盟／友好／中立／緊張／敵對），歷史變化寫事件。`mercPolicy.generosity|reliability` 1–5 給營運用。小勢力 300–600 字即可，但要有一句能被引用的信條（「慢，但不倒。」「傭兵的死不算陣亡。」）。`gameRefs` 連 `base:faction/…`、`base:frame/…`，只驗格式。

## 人物（characters）

必填 born／faction／role／relations／events；`kind` human／soul／other（古代機當先民寫）。寫人先寫**一件他做過的事**，再寫他是誰；駕駛員會死、死得平淡，但吼出來的那一回合寫得像歌劇。機魂人格是 S 級以上罕見現象——寫傳奇機魂（七號、手套、灰、阿鏽…）時點明罕見，一般機魂「只是數石頭回港」。與 base `persons/` 對應的人物填 `gameRefs: ["base:person/…"]`，姓名寫法一致（「葛西 蓮」空格）。

## 事件（events）與地點（places）

事件 300–1500 字、`## ` 小標 3–5 個、`consequences` 一句一條可被後續事件引用；tags `war`／`campaign`／`diplomacy`／`dig`／`tide`／`rumor`。地點每洲 ≥3（check.ts 驗）、`continent` 九選一、`status2108` 一句（守住／失守／蝕線上／封鎖中）。

## 文字潤飾準則（只改文字欄、不改 id／數值／引用）

**基調**：太空歌劇、不太現實、敢中二——冷硬潮濕的捕鯨船底色，蓋一層神話的光。意象優先於機制：先有畫面與名字再有數字；數字只在型號（II型、V4）與遊戲數值欄，不進敘述。東西是「長」出來的、「醒」過來的、「認」人的。黑色幽默與中二並存：角色知道招式名很誇張，照樣吼出來。

**禁用詞**（概念不是字）：電磁、電壓、電流、電池、伏特、瓦、焦耳、電子、電路、晶片、電腦、程式碼、演算法、量子、奈米、核融合、反應爐、口徑、毫米／mm、彈道學、軌道力學、推進劑、火箭燃料、Δv、公里／秒、聲納。替代：雷達→殼目、衛星→星哨、無線電→天網、飛彈→追矢、砲彈／子彈→矢、坦克→鐵龜、戰鬥機→鐵翼、電能→流光、熱量→燼、電弧→弧光、散熱→排燼、拘束彈→拘束矢、AI→機魂、程式→術式、電腦→算核。人名地名含同字不受限（瓦曼）。允許：氦／氣囊、地熱、論文（四千篇十分律論文是個笑話）。`lint_world.py` 會掃 world/，lore 自己 grep。

**句長與語感**：敘述句 15–35 字、對白 ≤20 字、一段 3–5 句；第二人稱現在式（事件、對白）、第三人稱過去式（lore body）；每段至少一個具體名詞（鹽霜、防火毯、拘束矢、魂核）、少形容詞堆疊；不解釋世界觀——讓名詞自己出現；結尾不下結論、不說教。中文標點全形、「」引號、・分隔複合名（迦耶伯格・倒棘之槍）、數字用阿拉伯數字只在遊戲欄位。

**可改與不可改**：可改 `name`／`summary`／`body`／`text`／`lines`／`choices[].text`／`ui.badge`／`phrase`／`title`／`aka`／`note`；不可改 `id`、任何數字、`tags`、引用（`faction/…`、`base:…`、`effect/…`）、`when`／`requires`／`effects` 結構、欄位增刪。改顯示名時全庫 grep 同名（lore、catalog、templates/default.json、ui 文字）一起改，REPORT 列對照表（舊→新）。`npm run check`、`node content/lore/check.ts`、黃金 hash 必須不變——潤飾不該動 hash；動了就是改到非文字欄。

**翻譯腔與 id 外露**：事件句不寫「受到了影響」「進行攻擊」；不讓 `shaken`、`player陣營` 這種識別字出現在玩家看得到的文字——找到就補 `name`／`ui.badge`，不是改 id。

## 常見錯誤

引用不存在 id；大勢力缺四小節；date 不在 period 內；開場後無 rumor；撞名；把機魂寫成有個性；餵養／獸欄／寵物語彙；數字進敘述；禁用詞；潤飾時順手改了數值或 tags；只改一處顯示名造成全庫不一致。
