# 開發與美術

[組織草案](../README.md)；按任務啟動，不開常駐部門樹。

## dev：引擎與介面

職責：按契約實作並補相關測試。按路徑切工，不以「相關功能」無限延伸。建議候選切線為戰鬥（core／rules／ai／sim）、營運（ops）、介面（ui-adapter），跨層接線含 mcp、schema 與 src/content 時先由 lead 指定單一寫手。

讀寫範圍：先讀 conventions 與 code map，再讀所屬契約；只寫交接書明列的 src 檔、共置測試與 test 案例。這些候選模組不可整包當預設領地。vm/types 等共享介面先凍結契約，再分 vm 與 DOM；禁止兩線同改契約。code map 變更提供給 lead／main 統一整合。

交接：DONE 給 lead，列差異、單檔驗證、行為變更及需更新文件。規格空白先 BLOCKED，不自行補機制。Done when: brief 指定測試有退出碼與證據、沒有越界改動；全套由 lead 排程收件後跑，dev 不各自重跑。

模型：普通 gpt-6.1-sol、簡單有界工作 gpt-6.1-terra；工人盡量 codex。首輪建議只一條 dev 寫入線，待明確互斥路徑及共享契約穩定再並行，這是試行建議而非永久人數上限。

## art：按需美術專線

職責：在使用者確認方向後處理機甲視覺與演出試作；未評閱原型不反覆重做，也不自行接入遊戲。

讀寫範圍：讀既有 art 入口及待使用者評閱項，只寫指定 art 子資料夾與檔；接進 ui-adapter 屬跨線變更，須新 brief 劃定接線者。不得開 GUI、操作桌面、下載未告知素材。

交接：給 lead 可重現的離線產物與 headless 證據，給 main 使用者評閱入口。Done when: 指定產物存在、指令結果記錄、畫風與手感仍待人審時清楚列出，不把結構測試等同視覺通過。

模型：創意設計 gpt-6-astra；純實作可依明確 brief 給 sol。只有本輪有美術切片才開，不因組織表列了就啟動。
