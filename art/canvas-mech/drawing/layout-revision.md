# 礁鷹緊湊組裝修訂提案

首圖已親看，v1.0 視覺不通過。這份是交核心實作的配置提案，不是 drawing 對核心的修改或新版凍結授權。保留目前 184 節點／94 葉及功能層樹。精確變更列在 [layout-revision.json](layout-revision.json)，位置全部是**語義樹直接父節點的局部座標**；未列欄位保持。尺寸修改須同步 size/envelope/usableBounds/具名接點，不能只改畫面位置。

目標是頭下緣插入弧胸，肩座與肩軸重疊，上臂承力樑連到肘軸，肘軸至前臂以加長的甲殼及現有雙桿形成實體。胸弧甲、下緣甲、寬腰節、股髖接形成連續軀幹。腿靠股框與膝軸重疊、脛伸縮桿延伸至踝、踝跨到足跟與趾根，不能只讓外甲相貼卻無承力路徑。

近臂原尺寸，遠臂縮為 0.90；遠腿 0.94，並收窄髖距。縮放由核心頂層肢體 localTransform 處理，rig rebase 必須保留結果，drawing 不自行縮放。這是固定視角深度提示；胸甲本身的偏置稜線及遠側明度會配合，仍非 3D。

近側待機預期：肩約 (715,345)、上臂 (715,415)、肘軸 (720,473)、前臂甲 (720,525)、手 (723,610)；近腿髖接約 (650,589)、膝軸 (650,715)、踝約 (654,862)。胸弧甲中心 (540,345)，頭艙中心 (535,260)，腰節中心 (550,537)。這些是方便核對的目標，不授權 viewer 另套偏移。

核心須自下向上重新計算**群組分配包絡**以涵蓋修改後子件，再由 configureMech 自上向下重新配置並完整驗證；不要為通過 containment 而改掉本提案的零件接合位置。既有連桿兩端接點與 restLength 要重新解算，idle／舉盾／低姿都檢查；若需補接點或橋接件，先提出而非偷偷填畫面。

修訂後必驗結構連續性：頭↔頸↔胸、胸肩座↔肩轂、肩↔上臂、上臂↔肘、肘↔前臂↔掌、腹腰↔兩髖、股框↔膝軸、脛桿↔踝↔足趾、砲握把↔掌、砲口↔機匣、盾臂接↔前臂。bounds 相交只是必要條件；核心凍結後還要真正 PNG 驗輪廓是否接合。肩及肘旋轉時亦不可露出斷裂空隙。

drawing 接到新 hash 後才改凍結對映；將擴大盾瓣相接邊、肩甲下緣及脛甲下端的實際輪廓，並把遠側表面壓暗。若首圖仍有空隙，回報核心或修葉輪廓，不在 viewer 補位。所有 PNG 驗收仍由領導安排。
