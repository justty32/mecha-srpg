# cx-bb-character：人物、傷勢、士氣與戰後結算候選片段

## 做了什麼

親讀專案 AGENTS.md、交接書指定的 investigation、user、data-files、design-notes，以及相關 wf 派發、寄信與整檔修改規則。讀完指定的四份 BB 拆解文件，整理成 21 個可獨立取捨的機制；涵蓋背景生成與聘用、天賦與成長、perk 與 trait、傷勢、士氣與心情、傷亡撤退、經驗與戰利品結算。

改寫以駕駛員為持久人物、機甲及部件為裝備，部位 HP 與分層損傷另存；人物傳傷由部位效果清單觸發。所有建議是候選方案，不是已定 spec；沒有提出具體平衡數值。沒有新增世界觀、程式碼或延伸主題。

## 產出

[fragment.json](fragment.json) 為 wf-table/1，21 列、九欄，編號 CHR-01 至 CHR-21；採用 2／改造 18／不採用 1。每列包含 BB 規則、指定拆解檔的完整標題來源、機甲改寫、裁示對應、建議、理由及一個待決問題。裁示引用是適配依據，不代表使用者已接受各候選機制。

固定三項驗收：REPORT 存在且四段齊全；tabledb CLI 讀取成功、count=21，九欄皆為非空字串且 recommendation 合法；逐列以單一迴圈執行檔案存在與 grep -F 標題核對。

source 核對 21/21 命中

容量 gate：兩個產物合計小於 300 KB；件數未超過 22。沒有追加程式編譯、全庫 lint、遊戲測試或其他驗收。

## 沒做到或證據不足的

CHR-10 的指定拆解主文只確認傷勢是人物效果及重算所有權，CHR-11 主文確認永久傷不在戰後刪除；暫時傷的按日恢復／條件抑制、永久傷不自然恢復但可由外部效果移除，僅由允許的 injury-rules.csv 補充確認。以 tabledb 篩讀 broken_arm_injury、broken_leg_injury、brain_damage_injury、broken_elbow_joint_injury；這張證據表不作 source 欄來源。兩列已在 bb_mechanic 明示證據層次，不能把標題命中視為主文已覆蓋全部傷勢細節。也讀取 trait-rules.csv 的前兩筆確認資料結構，未把它擴寫成額外特質規則。

限定來源沒有完整交代暫時傷與永久傷的生成門檻、抽選池及倖存機率，因此未填補這些規則。CHR-12 只提取來源可支持的情境士氣檢定；士氣全階段、崩潰行為及其機率仍缺完整拆解。CHR-14 僅據結果集合寫昏迷倖存者的回收與敗退後果，未推定每種致命傷的判定方式。

BB 拆解本身主要為靜態調查，原生生命週期、排程與部分掉落邊界未動態驗證；本線沒有宣稱原遊戲實測。沒有讀 vendor 或另開反編譯原碼、重跑 BB 工具、上網或修改 BB repo。補充讀取表格時曾由自寫臨時腳本誤傳 Path 物件，已改傳字串後成功；非工具或環境阻塞，無未解除阻塞。

## 需要決定的事

逐條待決問題已留在 fragment.json 的 open_question，不在此複製表格。優先拍板駕駛員永久傷、士氣失控、昏迷者救回條件，再定隨機成長、薪酬、經驗分配與回收物去向；其餘候選仍可各自採否。

若要把傷勢生成或完整士氣崩潰寫成正式規則，需要上游另行安排補齊拆解；本線不擴讀其他 BB 主題。結算防重屬機甲方案的改良建議，沒有冒充 BB 原有保證。
