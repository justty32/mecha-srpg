# resources — 獨佔資源的鎖（螢幕、鍵鼠、GUI 程式、裝置）

[WORKFLOWS](../WORKFLOWS.md)｜[INDEX](../INDEX.md)

實體／獨佔資源的使用權由**頂層 agent（調度者）分配**，其他 agent 要用先申請鎖。搶資源**不會報錯**，只會讓兩邊的觀測都不可信——所以鎖是**強制的，不是禮貌**。

**何時用**：實際驅動或觀看桌面（送鍵、點滑鼠、截圖、開 GUI、headful 瀏覽器），或獨佔某個執行中的程式、某台裝置、某個 DB 工作區。
headful 瀏覽器自動化**即使不注入鍵鼠**，仍會開可見視窗佔住螢幕，**所以照樣要取桌面鎖**。
**何時不用**：純運算、讀寫檔、編譯、跑測試、寫文件——一律不取鎖。CPU 這類不可鎖的共享資源改用限流（見下）。

## 第一條規則：使用者優先

**本專案更嚴：鍵盤、滑鼠、螢幕對所有 agent 一律禁區**——不送按鍵、不截圖、不開 GUI 視窗、不開 headful 瀏覽器，**沒有鎖可拿**；Godot 只准 `godot-mono --headless`。真要實機操作或看畫面 → 在 [WAIT_USER](../WAIT_USER.md) 記一行請使用者親自做。下面的鎖機制留給將來真的出現獨佔資源時用。
**沒有可靠的偵測方式，所以預設當他在**，除非他親口說「我不在」「你去跑」。不要拿「螢幕鎖了」「滑鼠沒動」推論——他去倒杯水就誤判。

## Done when

- 收工時 `ls ~/shared_agent_locks/` 沒有本專案的鎖（目錄不存在也算）。
- 下方資源表每列的「鎖路徑」與「取得順序」非空。

## 流程

### 取得

`mkdir` 是原子操作，用它當鎖：

```sh
LOCK=~/shared_agent_locks/<資源>.lock
mkdir -p "$(dirname "$LOCK")"
mkdir "$LOCK" 2>/dev/null \
  && echo "$(date -Is) <我是誰> <用途與預估時長>" > "$LOCK/owner" \
  && echo ACQUIRED \
  || { echo BUSY; cat "$LOCK/owner"; }
```

`BUSY` 就**別做**那件事——去做不需鎖的部分，或寄一封 `BLOCKED` 給上游（見 [inbox/PROTOCOL](inbox/PROTOCOL.md)）。

### 釋放

**先讀 `owner` 確認是自己的**，再刪；不是自己的鎖絕不強拆。

```sh
grep -q '<我是誰>' "$LOCK/owner" && rm -rf "$LOCK"
```

用完立刻放。事情做完但鎖還在，等於整條線被你擋住。

### 多個鎖：順序固定

**取得依外層→內層，釋放反序。** 兩個 agent 用相反順序拿就死鎖。外層＝範圍大的（桌面／螢幕），內層＝範圍小的（某支程式）。順序寫死在下表，不臨場判斷。

### 不可鎖的共享資源：限流

CPU、網路頻寬鎖不了，改**限流**：重運算一律 `nice -n 19 <指令>`。**用到 80% 是上限不是目標**——這是使用者的機器，不是機房，跑得完就好，使用者在電腦前時尤其留餘裕。限流**按行程樹**（從自己啟動的 PID 往下），不要按名稱掃，會打到別人的實例。

## 資源登記表

| 資源 | 鎖路徑 | 取得順序 | 誰會搶 | 備註 |
|------|--------|---------|--------|------|
| 螢幕／鍵鼠／GUI | （不發鎖）| — | 使用者本人 | 全專案禁區，任何線都不准用 |
| CPU（測試、Godot headless、編譯 `mtcore`）| （不鎖）| — | 全部線 | 用 `nice -n 19` 限流；平行線多時錯開重運算 |

## 收工檢查

1. `ls ~/shared_agent_locks/` 沒有本專案的鎖。
2. 沒有自己起的殘留行程（用 `ps -eo comm= | grep -x <名稱>` 比對 `comm`，別用 `pgrep -f <名稱>`——命令列裡就有那個字串，會匹配到檢查自己）。
3. 動過的共用設定回到原狀。
4. **鎖路徑指向的目錄若被刪掉，「已釋放」檢查會恆真**——鎖目錄搬家或被清掉時要同步改檢查，否則你在檢查一個不存在的路徑。

## 交接

- 要使用者親自讓出鍵鼠／實機操作 → [WAIT_USER](../WAIT_USER.md) 一行。
- 哪條線可以拿哪個鎖，由交接書指定 → [dispatch](dispatch/README.md)。
