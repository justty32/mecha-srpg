# world-pillars／bio-battle — 生物系與怪獸、戰鬥結構、意圖與指揮（B1–B11）

### B1 生物系兩類：屍體改裝（無意識、安全、貴、不成長）與活捕（有意識、馴養不了、硬壓）

**為什麼**：「兩者差別主要在怪獸有無意識——活捕的怪獸有意識……而且通常是馴養不了的。屍體改裝本質上是把怪獸身體當成一套裝甲……挺安全，但開銷大，除了高級怪獸外通常不會這樣做。」活捕「拿掉『馴』這一步」。
**做**：活捕＝捕到直接上拘束器，意識始終對抗，同調／承擔／暴走保留；屍體改裝＝無本能池、不暴走、不成長，開銷在營運層（吃一顆同級核）。
**不做**：寫馴化期、飼養日數；活捕怪獸聽話、忠誠；屍體機暴走或成長。
→ bio-mechs「生物系分兩類」「屍體改裝 vs 活捕的本質差別」「活捕系的兩條確認」

### B2 怪獸不是畜牲：沒有餵養

**為什麼**：「沒有餵養。怪獸就是怪獸，不要把它當畜牲。」
**做**：營運只有拘束器磨損、掙脫事件、維護、同調；文字寫壓制與防範——「牠每天都在掙」。
**不做**：餵、飼料、獸欄、飢餓、寵物、「乖」、「牠認得你」、親暱互動；把拘束艙寫成牧場或馬廄。
→ bio-mechs「沒有餵養」

### B3 族別維持是例外，不是餵：蟲族獸族吞屍保持活性，異形菌絲另有機制

**為什麼**：「怪獸種類很多，例如蟲族，也可以拿一些怪獸屍體丟給牠保持活性；獸族也是。」「異形與菌絲用其他的維持機制（不吞屍）。」
**做**：族行為一潮月一次、綁大潮節拍——蟲獸投屍（`devour`，用「丟」不用「餵」）、異形潮浸、菌絲修剪；做成族別資料與效果。
**不做**：全族共通的飢餓值或每日維持；異形菌絲也吞屍；把投屍寫成餵食時間。
→ bio-mechs「族別例外」「三類機甲的營運主軸」首句

### B4 三類機甲的營運主軸：機械＝改裝保養＋培養機魂，古代＝駕駛員心智成長，生物＝對抗怪獸、防止失控

**為什麼**：生物系「同樣可以改裝保養，但營運時其實也是和怪獸對抗的感覺——要防止失控之類」。
**做**：生物系事件系列寫拘束艙（磨損、夜撞、掙脫演習）；古代系事件寫駕駛員的信念、繼承前任的特質與怨；機械系事件寫技師工時、鍛研、陪機魂。
**不做**：生物系寫成養寵物或照顧；古代系寫成修機器、換零件；機械系寫出靈異感情（那是機魂 S 級的事）。
→ bio-mechs「三類機甲的營運主軸」

### B5 怪獸意識不算人物

**為什麼**：活捕系確認 (2)：「怪獸意識不算人物（不同於機魂，不用人物資料骨架）」。
**做**：以機體側資料表達——`instinct` 池、狂暴意志、族 `aiProfile`；bio frame 只有 pilot 座。
**不做**：給怪獸 person 檔、soul 座、對白、relations；把牠寫成會溝通的夥伴。
→ bio-mechs「活捕系的兩條確認」

### B6 生物系命名：登記號 → 小名 → 凶名；二名只給 A 級以上

**為什麼**：「通常沒有特別的命名」；登記號「直接打上編號即可（不要用『獸欄』那類字眼）」；小名「使用久了才會有，如『獨眼』『老黑』」；凶名「外人給的」；二名參考魔物獵人，「A 級以上的怪獸才有，發揮中二給牠一個稱號，如『赤眼兇星』」。
**做**：frame `name` 是登記號式；小名是長期使用後的事件；凶名與二名由名氣／等級驅動，野生 A 級即有二名、捕獲後沿用；二名寫「牠做過的事＋牠的樣子」四字為主。
**不做**：B 級以下給二名；在 frame 取寵物名；一捕到就有小名；登記號含畜牧字眼。
→ bio-mechs「生物系機甲的命名」

### B7 BB 式：機甲就是裝備、駕駛員是人物；部位有 HP、層是序列、資源池多種多樣、後果資料驅動

**為什麼**：「走 Battle Brothers 式，機甲就是裝備」；「部位種類很多、依機體而異……每個部位都有 HP」；層「裝甲層／內層／護盾層／內臟層……多種多樣」；資源「不是『第二資源』一種，是多種多樣的資源：生物酸儲量／電能儲量／轉速」；部位打壞與傳到駕駛員的後果「多種多樣」。
**做**：body plan 是資料；層有序列各有 HP 與類型；每台零到多個池、各有閾值效果，池名用風格名（流光、燼、本能、怒…）；後果掛效果清單。
**不做**：把熱量當所有機甲共通第二資源；人形骨架寫死；單一「失能」規則；駕駛員只是數值。
→ [mechanics 2026-10-23 裁示](../../planning/design-notes/mechanics.md#2026-10-23-裁示含當晚多次補充)

### B8 以「意圖受挫撤退」取代平手

**為什麼**：「平手……其實怪獸和勢力，他們都會有自己意圖，如果發現達不到，就可能會撤退。」
**做**：戰場每一方（含怪獸、勢力部隊）帶意圖（獵食、守巢、奪點、護送、殲滅）；達不到就撤離，戰鬥自然收場；撤退方算未達成、對手算守住／擊退，營運層照此回寫；巢穴、潮錨等不能動的不撤，護衛可撤。
**不做**：打滿輪數平手當常態；情境或 lore 寫「堅持到最後一人」；撤退寫成失敗的恥辱而非戰術。
→ [mechanics「以『意圖受挫撤退』取代平手」](../../planning/design-notes/mechanics.md#2026-10-23-裁示含當晚多次補充)

### B9 勝利不必全殲

**為什麼**：「所以不是說必須全殲滅。」
**做**：契約與情境主目標多用擊退、守住、驅離、斬首潮錨；讓對手意圖受挫而撤退就是勝利；全殲只是其中一種。
**不做**：所有契約主目標都是 eliminate；lore 戰役一律寫成殲滅戰；把「敵方撤退」記成平手。
→ [mechanics 同段末句](../../planning/design-notes/mechanics.md#2026-10-23-裁示含當晚多次補充)

### B10 意圖分兩層：陣營指揮者與個體本能；怪獸指揮者稀少且低智

**為什麼**：「個體也會有自己的意圖，比如怪獸受傷過重就會逃跑，也有些會發狂。機甲駕駛員則是會撤退。也可能指揮者會依據戰術考量讓一些受損過重、補給不夠的，或是狀態不好的，暫時移到戰場後方。怪獸那邊也會有指揮者，但很少，而且智能也不高。」
**做**：怪獸個體重傷逃跑或因族性發狂；駕駛員依士氣與傷勢自行撤退；人類指揮者做輪替（受損、缺補給、狀態差的暫撤後方）；怪獸指揮者只限母體、潮錨、王級，只會集結、圍攻、護巢；指揮者陣亡則退化為個體本能、可能潰散。
**不做**：怪獸群打出井然有序的戰術；每隻怪獸死戰到底；人類陣營只會全衝或全撤。
→ [mechanics「個體意圖與指揮者」](../../planning/design-notes/mechanics.md#2026-10-23-裁示含當晚多次補充)

### B11 戰鬥規模不限、地圖有大有小、戰場是真方格

**為什麼**：「一場戰鬥不限制機甲數量；地圖有大有小；一局時長不限」「不要字元格，要方格（真的格子，DOM／CSS 畫）」；UI「不走 MUD／純文字」。
**做**：地圖尺寸是資料（16×16 決鬥到 60×60 參戰型）；情境可多方多單位；格子用 CSS 形狀、顏色、文字標記。
**不做**：假設小隊上限；用字元格或純文字描述戰場；寫美術資產需求。
→ [mechanics「戰鬥規模與地圖」「地圖呈現」](../../planning/design-notes/mechanics.md#2026-10-23-裁示含當晚多次補充)
